# AI workflow log

Evidence for the **Best AI-Powered Workflow Story** bonus prize, collected while we build,
not reconstructed at the end.

## What the judges look for

Devpost rules, section 6: bonus submissions are judged on *"how clearly and completely they
show the team's use of JetBrains IDEs, AI Coding Agent Junie or JetBrains Air to build the
Project."* We submit a write-up file in the repo ([`AI_SHOWCASE.md`](../../AI_SHOWCASE.md)),
which the rules allow, and link it on Devpost. The rules also encourage committing the
`.junie` / `.air` / `.idea` folders as evidence.

So every entry should make three things obvious: **which JetBrains tool**, **what it did**,
and **what the human did on top**. Claude (planning, Linear, PR review) is part of the story,
but Junie / Air / JetBrains AI Assistant must be the main character.

## The routine (2 minutes per entry)

1. Finish a task where AI did real work (a feature, a bug hunt, an analysis, a refactor).
2. `python scripts/ai-log/new_entry.py "short title" --tool Junie --issue MUH-8`
   creates `log/YYYY-MM-DD-short-title.md` from the template, prefilled.
3. Fill the sections. *What we changed and why* is the part that wins: be honest about what
   the AI got wrong.
4. Optional: a cropped screenshot in `screenshots/` (see the rules there).
5. Commit it with the code, in the same PR.

Not every task needs an entry. Aim for 2–4 good ones a week, and mark the best with
`highlight: true`.

## Captured automatically

| Source | How |
|---|---|
| **Junie** | [`.junie/guidelines.md`](../../.junie/guidelines.md) asks Junie to draft a log entry at the end of each task. Review it, then keep or delete. |
| **Pull requests** | The PR template has an *AI usage* section. When a PR with that section filled is merged, the `ai-log` workflow commits `log/auto/pr-<n>.md`. |
| **Linear** | Add the label `ai-assisted` to issues where AI did most of the work. Claude can pull those issues and their comments into the log on request. |
| **Summary** | `python scripts/ai-log/summarize.py` rebuilds [`SUMMARY.md`](SUMMARY.md): entries per tool and phase, time saved, highlight list, timeline. |

## Data rule (hackathon licence)

GRID data must never enter this folder: no event JSON, no `.jsonl` lines, no per-round
tables, not in prompts pasted here and not in screenshots. Aggregate numbers (accuracy,
counts, percentages) are fine. CI runs `scripts/check-no-data.sh` on every push.

